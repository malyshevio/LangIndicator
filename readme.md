# Индикатор раскладки у курсора ввода

GNOME Shell-расширение (JavaScript/GJS), которое показывает текущую раскладку
клавиатуры («RU», «EN» и т.п.) всплывающим индикатором **прямо у текстовой
каретки** в активном приложении. Индикатор появляется при переключении раскладки
и при запуске утилиты.

**Только Wayland, GNOME Shell 45+.**

Обычное Wayland-приложение (Rust или Go) не может получить позицию каретки
другого приложения из-за изоляции композитора, поэтому GUI-слой — это
обязательно расширение GNOME Shell. Rust/Go зарезервирован только под
опциональный D-Bus-помощник для XKB (`dbus/`, пока не реализован).

---

## 1. Требования и ограничения

- **Целевая среда:** Linux + Wayland, GNOME Shell 47+ (`protocol_to_stage_rect`).
- **Позиционирование (критично):** индикатор появляется **строго у каретки**, а не у курсора мыши. Позиция мыши не является допустимым fallback-ом. Там, где точное позиционирование у каретки технически невозможно, это фиксируется как ограничение, а не подменяется позицией мыши.
- **Поведение:** индикатор постоянно находится у каретки активного окна и
  следует за ней (печать, стрелки, backspace). При потере фокуса/смене окна
  скрывается и появляется у каретки нового окна.
- **Триггеры:** 1) переключение раскладки (обновляет текст); 2) запуск/включение
  расширения (показывает текущую раскладку у каретки); 3) фокус в текстовом поле.
- **Стек:** отображение — GNOME Shell Extension (GJS). Rust/Go — только вспомогательные задачи (мониторинг XKB, D-Bus), **не как GUI-слой**.
- **Терминал:** не требуется.

## 2. Как получают позицию каретки

Коротко; подробности, сниппеты и источники — в [docs/research.md](docs/research.md).

- **IBus panel service (запасной путь):** сигналы `set-cursor-location` / `set-cursor-location-relative` от `getIBusManager()._panelService`. Работает для приложений, сообщающих позицию в input-method (GTK/Qt с IBus-модулем). Особенности: позиция не приходит при простом фокусе и может отставать на один отчёт — поэтому IBus используется как запасной источник.
- **AT-SPI (основной источник позиции):** события `object:text-caret-moved` и `object:state-changed:focused` через штатный `FocusCaretTracker` Shell + `atspi_text_get_character_extents` (как в GNOME Shell Magnifier). Даёт текущую позицию и работает на стрелках/backspace, если приложение отдаёт a11y-каретку.
- **Смена раскладки:** `getInputSourceManager()`, сигнал `current-source-changed`.
- **Оверлей:** `BoxPointer.BoxPointer` + dummy-актор + `Main.layoutManager.addTopChrome(...)`, чтобы не перехватывать фокус ввода.

**Почему не автономное Rust/Go-приложение:** сторонний Wayland-клиент не видит каретку другого приложения (протокол `zwp_text_input_v3` отдаёт `set_cursor_rectangle` только композитору; опыт fcitx5 с нулевыми `SetSpotRect`). Поэтому GUI-слой живёт внутри композитора.

## 3. Архитектура и стек

| Компонент | Технология | Роль |
| :--- | :--- | :--- |
| **GNOME Shell Extension** | JavaScript (GJS) | Вся логика: отслеживание раскладки, получение позиции каретки, отрисовка оверлея (Clutter/BoxPointer). |
| **D-Bus-сервис (опционально, `dbus/`)** | Rust / Go | Публикация XKB-состояния (`libxkbcommon` / `xkbcli`); расширение подписывается на сигналы. Упрощает синхронизацию, но не обязателен и пока не реализован. |

## 4. Структура проекта

```
extension/extension.js   — вся реализация (один файл)
extension/metadata.json  — uuid и поддерживаемые версии Shell
extension/stylesheet.css — стиль оверлея
docs/research.md         — исследование позиции каретки и API
scripts/install.sh       — установка (symlink) для разработки
dbus/                    — заглушка под опциональный D-Bus-координатор
```

## 5. Установка и запуск

Требуется настоящая GNOME Shell Wayland-сессия — в контейнере/CI расширение не запустить.

```bash
./scripts/install.sh
gnome-extensions enable lang-indicator@malyshevio.github.io
# Wayland: перелогиниться (Alt+F2 → 'r' НЕ работает)
journalctl -f -o cat | grep LangIndicator     # логи расширения
```

Единственная локальная проверка — синтаксис (ESM):

```bash
cp extension/extension.js /tmp/extension.mjs && node --check /tmp/extension.mjs
```

## 6. План реализации

Фазы соответствуют спринтам 0–3 (трекинг — в YouGile, проект `LangIndicator`, префикс `LAN`).

1. **Спринт 0 — Исследование:** ✅ выполнено, см. `docs/research.md`.
2. **Спринт 1 — Прототип:** минимальное расширение, показывающее «RU»/«EN» у каретки (IBus + AT-SPI fallback). Зафиксировать, для каких приложений (GTK, Qt, Electron) позиция доступна, а для каких — нет.
3. **Спринты 2–3 — Унификация и полировка:** опциональный D-Bus-координатор (Rust, `zbus`); настройки (длительность показа, шрифт, цвета); гарантия, что оверлей не перехватывает фокус; тесты в GNOME Wayland.

## 7. Критерии приёмки

- В GNOME Wayland при переключении раскладки в текстовом поле (например, gedit или Firefox) индикатор появляется **рядом с кареткой**, а не у курсора мыши.
- При запуске утилиты текущая раскладка отображается у каретки (если фокус находится в текстовом поле).
- Позиционирование у курсора мыши **не используется**; для случаев, где позиция каретки недоступна, указано ограничение.
- Код собирается и работает в GNOME.

---

## 8. Известные ограничения

- Позиция есть только пока приложение сообщает её в input-method (IBus) или a11y; иначе индикатор не показывается (и **не** подставляется позиция мыши).
- Возможны задержки обновления позиции (Better IBus ставит debounce ~50 мс на `notify::focus-window`).
- Не все приложения (Electron, кастомные виджеты) корректно отдают a11y-каретку (известные баги: mutter#3963 — нет `text-caret-moved` для `ClutterText`).
- wlroots (Sway и др.) без модификации композитора не поддерживаются.
